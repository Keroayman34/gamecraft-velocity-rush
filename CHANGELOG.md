### Phase 5 — T5.1/T5.2/T5.3: input reset seam, data-driven vehicle rig, telemetry & chase camera (2026-11-09 — T5.1/T5.2/T5.3 complete; Phase 5 remained in progress pending T5.5)
- **Input (T5.1, owner-accepted):** added `AppState` and `IAppStateSource` to `VelocityRush.Core`; `LegacyKeyboardInputAdapter` now binds a state source through the composition root and performs a full driving-input/intent reset on every accepted `StateChanged` transition, without referencing the future GameFlow implementation. Added EditMode coverage for reset, idempotent binding, rebinding, unbinding, and `OnDestroy` subscription release.
- **Telemetry contract:** added `IVehicleTelemetry` and the immutable `readonly struct VehicleTelemetry` in `VelocityRush.Core` (speed, signed forward/lateral speed, wheel slip, grounded). Telemetry is polled, event-free, and sanitizes non-finite or negative physics readings.
- **Vehicle profile (T5.2):** `VehiclePhysicsProfile` now drives engine torque falloff (`AnimationCurve`), front/rear brake bias, steering speed sensitivity (`AnimationCurve`), suspension, friction, rigidbody, and wheel parameters. `TryValidate` rejects non-positive mass/travel, out-of-range bias, null/empty curves, non-finite or negative curve keys, out-of-order keys, and curve values outside 0..1. The authored prototype asset serializes the placeholder response values explicitly.
- **Vehicle controller (T5.2):** `VehicleController` implements `IVehicleTelemetry`, applies the engine curve and per-axle brake bias, publishes telemetry once per `FixedUpdate` using struct-only wheel queries and a preallocated wheel array, and keeps the single rear-wheel-drive prototype code path. Pure mapping additions in `VehicleControlMath` (curve-scaled torque/steering and bias-aware axle braking) are Unity-API-free and EditMode-tested.
- **Camera (T5.3):** `CameraProfile` gained rest/top field-of-view and a speed reference. `VehicleCameraRig` now requires an explicitly assigned `IVehicleTelemetry` source (no direct `Rigidbody` reads), uses a critically damped translation spring and a deterministic critically damped quaternion spring for rotation, applies a linear FOV ramp, and performs non-allocating sphere-cast collision avoidance with a preallocated hit buffer and minimum-distance clamp. Paused time freezes both smoothing springs.
- **Track layer:** added the dedicated `Track` layer (index 8) and assigned the prototype track/environment objects in `TestTrack` to it; the camera rig's serialized obstruction mask is Track-only. Gameplay layers, the physics collision matrix, and the vehicle layer are unchanged.
- Added EditMode coverage for FOV/bias/curve validation, curve-scaled control math, telemetry sanitization, and the rotation spring (pause freeze, snap, no overshoot, convergence). Added two PlayMode tests covering telemetry-source resolution, Track-only obstruction wiring, finite camera pose, distance bounds, and FOV bounds.
- Validation (actual project, Unity 6000.6.8f1 batch mode): compile **0 errors / 0 warnings**; EditMode **160/160**; PlayMode **6/6**; zero failures/skips. At that point Phase 5 remained open pending T5.5 and browser runtime validation; no WebGL build was executed by that work.

### Phase 5 — T5.4: minimal race loop, checkpoints & in-scene retry (development prototype, 2026-11-08 — actual-project validation passed)
- Added the first minimal race loop on the existing straight `TestTrack`: explicit `Countdown → Running → Finished` states, a configurable 2 s prototype countdown, and a monotonic `Stopwatch` race timer that starts only at Running, excludes countdown time, and freezes permanently at Finished.
- Added three ordered checkpoint trigger gates plus a finish gate. Only the next expected checkpoint is accepted; out-of-order, duplicate, negative, and post-finish indices are rejected. The finish is blocked until every checkpoint is accepted, and duplicate trigger contacts cannot emit a second result.
- Added immutable `RaceResult` (elapsed seconds, accepted/required checkpoint count, completion) and exactly-once `RaceFinished` delivery. `RaceController` owns the prototype lifecycle and forwards the result to an explicit observer/logger; no Results UI, scoring, rewards, progression, save, multiplayer, AI, or audio was added.
- Added in-scene retry through the existing `IAppInput.RetryPressed` intent: state, checkpoint progress, timer, result guards, vehicle spawn pose, and linear/angular velocity are reset without `SceneManager.LoadScene`, additive reload, or object recreation.
- Added pure EditMode coverage for the race rules (injected deterministic clock, transitions, timer, ordered checkpoints, finish gating, exactly-once result, retry reset) and the owner-authorized `VelocityRush.Tests.PlayMode` assembly with four real PlayMode tests (countdown, scripted checkpoint/finish sequence, retry intent/scene reuse, vehicle pose/velocity reset).
- `TestTrack` wiring is limited to simple trigger colliders and one `RaceController`; the existing road, barriers, spawn point, vehicle, camera, input adapter, Bootstrap, ProjectSettings, packages, layers, tags, and physics settings were preserved. No new Markdown file was created.
- Validation evidence (actual project, Unity 6000.6.8f1 batch mode): import/compile passed with **0 compiler errors and 0 warnings**; `VelocityRush.Tests.PlayMode.dll` was generated; full suites passed — EditMode **129/129**, PlayMode **4/4**, zero failures/skips. All `TestTrack` script references resolve to existing scripts; the three checkpoints report stable indices 0/1/2 at `z = −20 / 5 / 30` with the finish at `z = 45`; retry was verified to reuse the same scene instance and the same vehicle instance with no scene load/unload. An isolated-copy run earlier produced the same counts (129/129, 4/4). T5.4 is marked complete on this evidence.
